# 翻页动画：融合进 GPU 显示总线的实现

> **0.3.0-rc1 起的范围说明：** 本仓库只分发 GPU 融合实现的翻页动画，需要同时开启 GPU 显示后端。下文提到的第三方专用翻页库、`a5pro-resident` / `a5pro-control-once`、`ic_pageanim_sync` 以及 `pageanim.touch` / `pageanim.keys` / `pageanim.debounce` 属于贡献者分支的「独立库模式」，因无源码未并入，相关段落仅作为设计背景保留。

> 面向 **Hisense A5 Pro 经典版 HLTE203T / Android 10**。
> 一句话：翻页动画不再挂第二份 HWC，而是把「分块揭示」重写成**一次整屏波形的条带相位**，
> 逻辑住在 `libeinkgpu.so` 里，与 GPU 显示后端共用同一份 HWC，两个开关可同时打开、不用重启。

## 一、落在哪

| 位置 | 职责 |
| --- | --- |
| `native/service_fusion.hpp` | 读 `ctl` 字段与属性，得出「这一帧要不要分带、往哪个方向、几帧错峰」的 `Drive` |
| `native/service_gpu.cpp`（`hookUpdate`） | 唯一接入点：构造波形请求时写入 `bandDirection / bandRows / bandTail / bandStyle`，并在 `frame 0` 之后延长 A2 循环 |
| `native/service_waveform.hpp` | 着色器：按 `bandRows` 划分条带、算每带的 `delay`，未驱动区域输出中性字节 |
| `backend/lib/common.sh` | `inkctl apply` 时把 `pageanim.*` 翻译成 `debug.inkcontrol.fusion*` 属性 |
| `src/com/inkcontrol/features/fix/Hook.java` | system_server 侧随前台切换写 `fusion.reader`（名单命中=1） |
| `src/com/inkcontrol/features/motion/Hook.java` | 手势 / 音量键判定，写 `fusion.flip` |

HWC 只有一份：`display.gpu=1` 时挂 GPU 库（`a95b9f92…`），`pageanim.master=1` 只是在同一份库里打开分带驱动，
不需要重启、不争 `0x92fe4`、不附带常驻端。

## 二、数据流

```
App 配置 pageanim.{master,style,bands,spacing,reverse,readers,vkey}
   │  inkctl apply
   ▼
debug.inkcontrol.fusion / .drive / .armed / .style / .bands / .spacing / .reverse
   │                                    ▲
   │ hookUpdate 每帧读取                 │ system_server：前台包名 ∈ readers → .reader
   ▼                                    │               手势 / 音量键 → .flip
einkfusion::drive() → WaveRequest{bandDirection, bandRows, bandTail, bandStyle, totalFrames}
   ▼
着色器按条带相位逐带驱动 → 物理屏
```

## 三、门控：什么帧才分带

`inspect(ctl)` 从墨控自己的 `einktransition::Control` 读字段（`+0xbc/+0xc0` 宽高、`+0x15c` mode、
`+0x160` total、`+0xc8` remaining、`+0x2c8` region、`+0x280` blank、`+0x270` reset、`+0x278` transition），
`drive()` 与 `service_gpu.cpp` 一起要求全部满足：

| 条件 | 含义 |
| --- | --- |
| `fusion=1` 且 `fusion.drive=1` | 两个大功能都开（`display.gpu` + `pageanim.master`）才下发 |
| `armed=1` | 总闸门，由后端按 `pageanim.master` 写 |
| `reader=1` | 前台应用在「目标阅读器」名单里；名单为空恒为 0，即不触发 |
| `full` | 整屏 1440×720（`ctl` 里是转置后的宽高） |
| `waveFamily` | mode ∈ {1, 2, 5, 6, 8}，即 `segment()` 会生成 GPU 波形的帧 |
| `nonLocal` | `region==0` 且 `transition==0`，排除局部与区域叠加 |
| `total>=4`、`activeFrames>1` | 帧数够切成几段才有意义 |
| `motionMax==0`、`!blank`、`phase==Normal` | 这一帧没被「动画」接管、不是熄屏、不在过渡阶段 |

## 四、时序：条带相位与帧数预算

分带不是「拆成 N 次提交」，而是在**同一条波形**里让每个条带从不同帧开始走 LUT：

```
bandRows    = 720 / pageanim.bands        // 4..32 块 → 每带 180..22 行
steps       = 719 / bandRows + 1          // 带数
delay       = bandIndex * bandTail / (steps - 1)
totalFrames = activeFrames + bandTail + 1
```

三件事必须一起做，缺一就会出问题：

1. **每带要驱动到末帧**：`bandFrames = activeFrames - 1`（`validWave` 要求 `bandFrames < activeFrames`，
   这是唯一安全值）。一条带一旦启动就必须一路驱动到波形结束，否则末帧残留大片未驱动区域。
2. **总帧数要等量延长**：`frame 0` 的原厂调用之后，`extendTail()` 给 `ctl+0xc8` 与 `ctl+0x160` **同加** `bandTail`。
   帧号 `total - remaining` 不变，但 A2 循环多跑 `bandTail` 帧，每条带因此都能从 LUT 第 0 帧走满 `activeFrames`。
   失败或提前终止时 `restoreTail()` 撤回 `total`，避免原厂用扩展后的帧号越界访问 LUT。
3. **未驱动区域输出中性字节 0**（保持当前像素）。早期版本在这里送出控制模板的原始驱动字节，正是黑屏的来源。

`bandTail` 的算法：基数 `分带数 × 3/4` → 下限 4 → 按 `spacing/12` 缩放 → 夹在 `4..16` →
再受 `158 - activeFrames` 上限约束（总帧数上限 158）。

| bands | spacing | bandTail | 总帧数 |
| --- | --- | --- | --- |
| 4 | 12 | 4 | active+5 |
| 12 | 12 | 9 | active+10 |
| 12 | 40 | 16 | active+17 |
| 32 | 12 | 16 | active+17 |

代价是整屏刷新多几帧（10~17 帧，几十毫秒）。这是分阶段揭示的必然成本：先后顺序必须有时间预算。

## 五、展开形状与方向

`bandStyle` 把六种 `pageanim.style` 折成一维揭示次序 `coord`，再由 `coord / bandRows` 得到带号：

| style | 次序 |
| --- | --- |
| 0 横向展开 | `coord = row`（竖条，从左向右推） |
| 1 纵向展开 | `coord = x * 2`（横条，从上向下推） |
| 2 斜向 / 3 反斜向 | `(row ± x*2) / 2` |
| 4 环绕 / 5 中心 | 由 `(x, row)` 算到中心的环形距离，环绕取反相 |

`bandDirection` 只决定扫描走向：`1` 沿 `coord` 正向，`2` 取反（`coord = 719 - coord`）。

最终方向 = `pageanim.reverse`（属性 `fusion.reverse`）**异或** 本次操作判定 `fusion.flip`：

| 来源 | 写什么 |
| --- | --- |
| 手势（`motion/Hook.detectPageTurn`） | 抬手时判定：水平位移 ≥48px 且 ≥2 倍垂直位移算滑动；左滑或点右半屏＝下一页（写 `flip=1`），右滑或点左半屏＝上一页（`flip=0`）；竖向拖动、按住 >1.2s、屏幕中间不写 |
| 音量键（`motion/Hook.hookVolumeKeys`） | `PhoneWindowManager.interceptKeyBeforeQueueing` / `interceptKeyBeforeDispatching` 两处都挂；仅 `ACTION_DOWN` 且 `repeatCount==0`：音量+ → `flip=0`（上一页），音量- → `flip=1`（下一页）；受 `pageanim.vkey` 控制，关掉就回到跟手势走 |
| 值格式 | `flip = "<0或1> <uptime_ms>"`，`CLOCK_MONOTONIC` 与 `SystemClock.uptimeMillis` 同源，**4 秒后过期按正向处理** |

音量键本来没有「点在哪一边」的信息，不加这一层就会沿用上一次点击的方向 —— 这正是 `pageanim.vkey` 存在的原因。

## 六、触发范围

真正的判据只有一条：**前台应用是否在「目标阅读器」名单里**。

`features/fix/Hook.java` 复用已有的前台切换钩子 `EpdManagerService$1.begigResumeActivity`，
在门控之前比对 `RuntimeConfig.value("pageanim.readers")`（逗号分隔），命中写 `fusion.reader=1`、
否则写 `0`；只在包名变化时写一次，配置变更时清缓存。

- 名单为空 = 不触发（与原版语义一致，不是故障）；
- 后端 `inkctl apply` 只在属性尚未写过时给初值 `0`，避免冲掉当前前台状态。

融合模式拿不到触摸事件，所以**同一白名单应用内的整屏刷新也会播**（上下滚动、弹窗、页内重绘）：
波形字段里滚动与翻页的 `mode / region / blank / transition` 完全一致，唯一稳定的区分就是名单。
`pageanim.touch` / `pageanim.keys` / `pageanim.debounce` 三项在融合模式下不参与判断，只在
「未开 GPU 后端、改挂专用翻页动画库」的独立模式下生效（`pageanim.keys` 指「把音量键当翻页键」这个动作本身，
方向另由 `pageanim.vkey` 决定）。

## 七、与「动画」互斥

「全刷扫过」（`motion.gc_clear` → `gcsweep`）与融合分带都靠波形时序表达：

| | 表达方式 |
| --- | --- |
| 全刷扫过 | 起跑帧图 `request.cpuStartMap` + `maxDelay`（每像素错开几帧开始扫） |
| 融合分带 | `bandDirection` + `bandRows/bandTail`（着色器按行、按格延迟） |

两者叠加会互相覆盖，表现是「扫过方向被翻页风格带成斜的」。所以 `hookUpdate` 里融合分支排在 `motionDecide` 之后，
`motionMax>0` 时**融合直接让位**：用户为该场景显式选了动画，就不该再叠分带。

`gcsweep` 属性格式为 `gcsweep <spread> <dir> <style>`（`dir` = `ltr/rtl/ttb/btt`，
`style` = `horizontal/vertical/diag/antidiag/ring/center`），旧的两段格式仍按 `ltr` 解析。

## 八、属性与排查

```sh
getprop debug.inkcontrol.fusion          # 0/1 总开关（两个大功能都开才为 1）
getprop debug.inkcontrol.fusion.drive    # 是否真的驱动分带
getprop debug.inkcontrol.fusion.armed    # 总闸门
getprop debug.inkcontrol.fusion.reader   # 当前前台是否命中名单
getprop debug.inkcontrol.fusion.flip     # "<0或1> <uptime_ms>"，4 秒过期
setprop debug.inkcontrol.fusion.observe 1   # 每 64 帧采样打印 ctl 字段
setprop debug.inkcontrol.fusion.plan 1      # 逐帧打印条带相位
logcat -s EinkFusion EinkGPU
```

| 日志 | 说明 |
| --- | --- |
| `FUSION_OBS` | ctl 字段采样，用来确认门控卡在哪一项 |
| `FUSION_HIT` + `FUSION_BAND` | 命中一次分带，列出每条带的 y/h 与起止帧 |
| `FUSION_PHASE` | 当前帧落在哪条带（`plan=1` 时） |
| `FUSION_DRIVE` | 真正下发给波形请求的参数（dir/style/rows/tail/frames/active/total） |

**`screencap` 抓的是 Android 合成层，不是 EPD 物理送屏内容**：残影、黑屏、刷新是否干净只能目视物理屏，
或用 GPU 波形帧（`readingCaptureWindow` 的位图）判断。

## 九、限制与回退

- **无手势识别**：分不出滚动与翻页，同一名单内所有整屏 GC16 都会播（见第六节）。要精确区分需在
  system_server 侧 hook 输入分发并写一条手势属性，属未做项。
- **波形帧预算**：`bandTail` 上限 24、总帧数上限 158，超长波形的分带会被压缩。
- **面板级全刷**：刷新键走的 `forceClearGhosting` 不产生新合成帧，不会被拦成一次分带，而是把当前帧缓冲原样重刷。
- 回退：把 `pageanim.master` 或 `display.gpu` 任一关掉，`inkctl apply` 即把 `fusion*` 归零，回到原厂波形路径；
  属性即时生效，不用重启。

## 十、历史坑（改代码时别踩回去）

1. **`!drive` 分支送模板原始驱动字节** → 面板级全刷把中间态定格成黑底。现在输出中性字节 0。
2. **只错峰不延长**（`totalFrames = active + 1`）→ 后启动的带在 LUT 尾部被截断，像素停在中间灰阶 →
   旧页留下浅灰残影（「刷新不干净」）。必须 `active + bandTail + 1` 并 `extendTail`。
3. **`armed` 写成常量 1** → 唤出快捷面板、滑动列表也播分带。现在必须 `armed && reader`。
4. **拿 `bandFrames` 当「展开速度」** → 它被 `validWave` 约束在 `activeFrames` 以内，只能取 `activeFrames-1`；
   要调速度得把着色器里固定的 `row / bandRows` 改成 uniform。
5. **靠 `mode` 字段排除滚动** → 滚动与翻页的 `mode` 恒为同一个值，这条判据不成立。
