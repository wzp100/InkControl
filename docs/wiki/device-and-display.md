# 设备与显示链路

[English](device-and-display.en.md) · [Wiki](README.md)

## 设备基线

| 项目 | 当前研究与代码使用的基线 |
| --- | --- |
| 目标 | Hisense A5 Pro 经典版，黑白墨水屏 |
| 设备检查 | `HLTE203T`、Android 10 / API 29、arm64 |
| 显示输入 | 720 × 1440；GPU 研究使用 Mali-G52 |
| 平台 | ums512，历史内核记录 4.14.133 |
| 适配固件 | 后端检查底层构建号 `L1732.6.01.02` 与准确 HWC 哈希 |
| 已验证系统软件版本 | `ro.software.version` 为 `L1732.6.14.01.B10`（贡献者）与 `L1732.6.15.01.B10`（2026-11-11 冒烟测试）；两者构建号均为 `L1732.6.01.02`、原厂 HWC 哈希一致 |
| 私有输入 | `ci/inputs.json` 中的原厂与动画 HWC 两个哈希 |

这是本项目的适配基线，不是对其他固件或同系列设备的兼容承诺。原厂库和波形文件保持原样。

## 从应用到面板

```mermaid
flowchart LR
  A[应用与系统画面] --> B[SurfaceFlinger]
  B --> C[厂商 HWC 输入队列]
  C --> D[灰度与色调映射]
  D --> E[量化与抖动]
  E --> F[模式决策与历史状态]
  F --> G[WBF 波形查表]
  G --> H[扫描帧与驱动队列]
  H --> I[DRM / DPU / 黑白面板]
```

翻页动画的分块揭示也在这条 GPU 波形时序里实现（`native/service_fusion.hpp`），因此依赖 GPU 显示后端；没有独立的翻页显示库。

原厂 HWC 负责显示处理与扫描消费，墨控的 GPU helper 在匹配路径中承担图像、统计、波形及扫描计算。GPU 依赖 EGL/GLES 导入与同步；不支持或异常路径仍可能走原厂 CPU。框架事件、量化算法、波形选择和面板扫描是不同层次，不能用一个 GPU 计数代替全部状态。

## 模式、算法、波形

外部模式低字节 2 是清晰，3／4／5 是阅读族，6 是快速，9 是极速；0 为自动。内部选择与实际内部模式还会影响是否进入接管分支。视频另需 `0x400` 标记且实际选择 A2。完整判据见[算法](algorithms.md)。

WBF 研究中识别 INIT、DU、GC16、GL16、GLR16、GLD16、A2、DU4 八类表。表存在、独立核能生成、当前真实入口会调用，是三种不同证据；不能把研究中的八类能力直接写成生产版全部入口已验收。

原厂输入只有一个待处理槽，后到画面覆盖前者；它本身已经保留最新目标。驱动扫描队列与这个输入槽不同。历史 8 格环形队列实际可用 7 格；早期约 91ms 提前量来自特定版本与负载，不应直接套用到当前 GPU 版。

## 读性能数据时

波次、扫描帧数、提交耗时、GPU fence、首张/末张扫描时间、光学可见延迟分别记录。一次画面更新可以需要多张扫描帧；波次增长不能直接换算面板 FPS。USB 连接采样不能替代拔线功耗基线。
