# 大功能后端支持清单

> 适用版本：墨控 InkControl 0.2.6-r26（2026-11-08 更新）
> 设备：海信 A5 Pro 经典版（HLTE203T / Android 10）
> 本文档随源码保存在 `docs/`，面向使用者与协作者。

## 一、先说结论

| 大功能 | 需要 Magisk 后端模块？ | 需要「GPU 显示后端」？ | 其他前提 |
| --- | --- | --- | --- |
| 显示 | **是**（除 2 项外全是后端角色） | 大部分子项需要 | — |
| 锁屏主题 | 否（仅「消除锁屏细线」需要） | 仅「消除锁屏细线」需要 | LSPosed 钩 `com.android.systemui` |
| 翻页动画 | **是**（独立库模式需第三份 HWC 与常驻服务） | 独立库模式需 | r23 独立库模式与「GPU 显示后端」互斥、切换需重启；r26 融合模式两者可同时启用、不用重启，分带揭示由波形层实现，见 5.3 |
| 动画 | 否 | 仅波形类动画需要 | LSPosed 钩 `android`（system_server） |
| 自动刷新 | **否**（只有「自动开关无障碍服务」这一步要） | **否** | 无障碍服务由后端按总开关自动启停；没装后端则需手动在系统设置里开 |
| 字体 | **是** | 否 | Root（后端模块提供 `inkctl`） |
| 体感 | **否**（只有「自动开关无障碍服务」这一步要） | **否** | 无障碍服务由后端按开关自动启停；没装后端则需手动在系统设置里开 |
| 桌面 | 否 | 否 | LSPosed 钩 `com.hmct.vision`（桌面） |
| 系统增强 | 仅「刷新配置损坏自动还原」 | 否 | 其余子项 LSPosed 钩 `android` |
| 快捷面板修改 | 否 | 否 | LSPosed 钩 `com.android.systemui`；面板开关由 SystemUI 转到 App 进程写配置 |
| 实验室 | 是 | 是（两个实验项都挂在 GPU 后端下） | — |

回答三个具体问题：

1. **「自动刷新」和「体感」在后端模块未启用、或 GPU 显示后端未开启时，还能用吗？**
   **能。** 这两个大功能的配置角色都是 `system`（system_server 钩子），完全不经过 Magisk 后端模块，也不依赖 GPU 显示后端：
   - 自动刷新 = App 内无障碍服务（`RefreshService`）计数 → system_server 钩子（`features/refresh/Hook.java`）反射原厂 `EpdManagerService.forceClear()`，全走 LSPosed；
   - 体感 = App 内服务（`features/wave/WaveService.java`）监听近距离传感器 + system_server 钩子，同样不碰后端。
   前提是 **LSPosed 模块处于启用状态**（作用域含 `android`），且对应的无障碍服务已开启。装不装 Magisk 后端模块、开不开 GPU 显示后端，都不影响「统计 / 监听 / 刷新」这些实际动作；唯一经过后端的是「把服务写进系统无障碍列表」这一步——装了后端就由它在开关打开时自动加、关闭时自动撤（开机也会同步，并每 60 秒补一次），没装后端就要自己去系统设置里手动开。
2. **「字体」的修改需要后端 Magisk 模块支持吗？**
   **需要。** 字体替换走 root：`inkctl applyfont / fontlist`（后端模块 `bin/inkctl`）——点「应用」写进系统槽位后，替换全局字体；备份恢复、微扰 `font_scale` 也都由它做。没有后端模块就没有 `inkctl`，字体页的列表与应用都无法工作（App 侧读取列表也是走 root）。
3. **「GPU 显示后端」和「翻页动画」能同时开吗？**
   **目前不能。** 两者都要替换同一个 `/vendor/lib/hw/hwcomposer.ums512.so`，是单文件争用，不是开关叠加。后端里虽然放了两套库，但开机只挂一份；同时打开时翻页动画优先，`display.gpu` 的补丁 HWC 与 `libeinkgpu.so` 不生效。详见第五节。

## 二、「后端模块」「GPU 显示后端」是什么关系

- **Magisk 后端模块**（`inkcontrol_backend`）：提供 root 工具 `inkctl`、开机脚本（`post-fs-data.sh` / `service.sh`）、配置校验（`ic_validate`）、属性下发（`ic_properties`）、字体槽位操作等。它负责「把配置变成系统状态」。
- **GPU 显示后端**（`display.gpu`，配置键）：是后端模块里的一项功能——用打过补丁的 HWC（`hwcomposer.ums512.so`）+ 注入库 `libeinkgpu.so` 替换原厂显示库，提供 GPU 取帧、像素量化接管、触摸响应加速、全刷复用。它是后端模块的**子集**，不是独立组件。
- **翻页动画**（`pageanim.master`）：0.2.5-r23 起同一个后端模块里放了三份 HWC。独立库模式（未开 GPU 后端）按 `pageanim.master` 选挂翻页动画库、由 `service.sh` 拉起常驻端，与 GPU 后端互斥；0.2.6-r26 起 GPU 后端优先，两个开关可同时开、切换不用重启，翻页动画交给 `libeinkgpu` 融合分支，详见第五节与 5.3。
- 换 APK 后必须同批重装后端模块（checksums 校验），否则 `skip_mount` → ready=0，App 报「环境未就绪」。

## 三、逐大功能明细

### 1. 显示（角色 `backend`，依赖后端模块）

| 子项 | 需要 GPU 显示后端 | 说明 |
| --- | --- | --- |
| GPU 显示后端 | —（即本身） | 补丁 HWC + libeinkgpu，重启生效 |
| 清晰/阅读/快速/极速/视频 算法与迟滞 | 是 | 通过 `debug.eink.alg.*` 属性由 native 读取 |
| **改用原厂显示算法** | **否（且优先级更高）** | 2026-10-25 起：独立开关，不开 GPU 后端也能开；开启后 native 完全不接管像素量化（A2 二值与灰阶全走原厂 CPU 路径），GPU 只保留取帧、全刷复用与触摸响应 |
| 触摸响应加速 / 停顿后首次响应加速 | 是 | |
| 滑动时减少系统查询 / 阅读类应用改用极速刷新 | 否 | 后端脚本开机应用，不碰显示库 |
| 实验室两个实验项（GPU 参数缓存、旧版视频选择） | 是 | |

### 2. 锁屏（角色 `systemui`，LSPosed 钩 SystemUI）

- 自定义锁屏、天气、锁屏通知（2026-10-26 起单一开关：关闭即不显示，开启后选系统/微信来源）、倒数日、歌词、刷新方式等：**不需要后端模块**，只要 LSPosed 启用且作用域含 `com.android.systemui`。配置由 SystemUI 进程直接从 App 保护存储读取。原「隐藏锁屏通知」（`lock.notifyhide`）已并入「锁屏通知」。
- 例外：**消除锁屏细线**（`lock.dither`，点量化）依赖 `display.gpu`，需要后端模块 + GPU 后端。

### 3. 动画（角色 `system`，LSPosed 钩 system_server）

- 过渡动画总开关（`motion.master`）与基础过渡（方形展开/关键帧擦除）、关键帧数、停留、起点、方向、应用内小动画：**不需要后端模块**。
- 波形类动画（墨迹晕开 / 网点长大 / 扫描线 / 百叶窗）与「进入锁屏 / 唤醒过渡 / 全刷扫过」（`motion.gc_clear`）三个场景：需要 GPU 显示后端（经 `HwcBridge` 请求 HWC 波形），且必须关闭「改用原厂显示算法」——该开关会把 GPU 逐像素波形时序一并停用。
- **全刷扫过的方向是独立设置**（`motion.gc_direction`）：`gcsweep` 早先只把 `spread` 写进
  `debug.eink.motion.gc`，方向在 native 侧被写死 `ltr`，所以「擦除方向」对它无效。现在这条属性
  变成 `gcsweep <spread> <dir>`（旧格式仍按 ltr 解析），方向由「动画节奏 → 全刷扫过方向」控制，
  `auto` 保持原厂习惯「从左向右」。
- **波形动画与翻页动画融合互斥**：两者都靠波形时序表达。`motionMax>0`（本帧已被某个过渡接管）
  时融合分带让位，否则斜向分带会把扫过方向盖掉。

### 4. 自动刷新（角色 `system`）——**完全不需要后端**

见「一、结论」第 1 条。注意：自动刷新调用的是**原厂** `EpdManagerService.forceClear()`，与 GPU 后端的 GPU 全刷是两条路径；所以 GPU 后端显示「需重启」或未开启时，自动刷新照常启用、照常触发。

### 5. 字体（角色 `backend`）——**必须后端模块**

见「一、结论」第 2 条。`font.dir / font.pick / font.saf` 全部经 root（`inkctl`）读写 `/data/fonts/`：点「应用」写进系统槽位后，替换全局字体，与 GPU 显示后端无关。

### 6. 体感（角色 `system`）——**完全不需要后端**

见「一、结论」第 1 条。「墨控体感」服务由后端按「遮挡息屏 / 移开唤醒」开关自动启停（**打开开关会自动打开相关无障碍服务**，两个都关就撤掉），开机时同样同步；没装后端才需要手动去系统无障碍里开。服务和自动刷新一样跑在独立的小进程 `:motion` 里，界面进程被杀不影响它。原「体感息屏唤醒」总开关（`wave.master`）已下线：遮挡息屏 / 移开唤醒各自就是开关，两个都关时服务不监听传感器；「遮挡延时」并入「行为」列表。

### 7. 桌面（角色 `launcher`，LSPosed 钩 `com.hmct.vision`）

- 桌面主题、图标/壁纸/组件换肤：**不需要后端模块**。

### 8. 系统增强

- 稳定性三项（`fix.exceptions / fix.configlock / guard.config`）与刷新行为两项（`fix.modes / fix.video`）、调用方校验（`fix.permissions`）：`system` 角色走 LSPosed，**不需要后端模块**；
- 例外：**刷新配置损坏自动还原**（`guard.config`）是 `backend` 角色，开机脚本里执行，需要后端模块（不需要 GPU 后端）；
- 原「Google 设置图标修复」（`fix.google`）已于 2026-10-25 **整体删除**（当前固件放在拆分包里、覆盖从未生效），旧配置里的残留键已被 App 与后端双侧容忍。

### 9. 翻页动画（角色 `backend`，依赖后端模块）

- 需要后端模块：HWC 派生库、`a5pro-resident` / `a5pro-control-once`、配置到 `settings.conf` 的翻译（`ic_pageanim_sync`）与开机拉起都在模块里；没有后端就没有这些文件。
- **不需要 GPU 显示后端**，反而与它互斥（见第五节）。开启期间 `libeinkgpu.so` 不挂载，所以墨控的分模式算法、迟滞、触摸加速、波形动画与「全刷扫过」全部停用。
- `pageanim.master` 是 `REBOOT` 项：只改配置不重启不会换库。

### 10. 快捷面板修改（角色 `systemui`，LSPosed 钩 SystemUI）

- 面板本身的按钮替换、图标与动作都在 SystemUI 进程里完成，**不需要后端模块、不需要 GPU 显示后端**。
- 「自动刷新」「遮挡息屏」「翻页动画」这几个按钮点一下是开关：SystemUI 没有墨控私有目录的写权限，调用 `ConfigProvider` 的 `toggle` 把写盘与 root 应用转给 App 进程；App 收到 `panel-toggle` 通知后重读快照并重画，界面上的开关样式才跟着变。App 不在前台时没有界面可刷新，下次打开会自动重读最新配置。
- 「锁屏主题」单击改为直接进锁屏样式页，不再就地关掉整套锁屏。
- **墨控被强制停止时**：海信的进程管控会禁止 SystemUI 拉起该包的 provider（`Unknown authority com.inkcontrol.state`）。`PanelHook` 检测到 provider 不可用时显式启动透明页 `PanelToggleActivity`（厂商只拦 provider/service 启动，不拦 Activity），由它把同一条 toggle 交给 `ConfigProvider` 完成后立刻结束，焦点不离开当前界面。写配置仍必须由墨控自己的进程完成，但拉起的是无界面空壳，不是打开应用。

## 四、App 界面中的判定规则（实现参考）

- 波形能力属性：后端 `post-fs-data.sh` 调 `ic_motion_caps` 从 `libeinkgpu` 的 `EINK_MOTION_V2:` / `EINK_LOCK_MOTION_V1:` 标记解析，写入 `debug.eink.motion.cap` / `lockcap`；这是 system_server 能否请求波形动画的唯一依据（此前无人下发，导致波形类动画一直静默失效）。
- `FeatureService.needsWaveBackend()`：`motion.lock / motion.unlock / motion.gc_clear` 三个场景加 `ink/dots/scan/blind` 四种波形值 → 运行时要求 `display.gpu`；
- `FeatureDefinition.role`：`backend` = 后端模块角色，`system / systemui / launcher` = LSPosed 钩子角色，与后端无关；
- 状态回执：`backend` 角色看 `applied.txt / boot.txt / runtime.json`；钩子角色看各进程上报的运行回执。

## 五、GPU 显示后端与翻页动画为什么不能同时启用（0.2.5-r23 历史结论）

> 以下是 r23 独立库模式的分析，仍适用于「未开 GPU 后端、单独用翻页动画」的场景。
> 0.2.6-r26 起 GPU 后端优先，两个开关可同时启用且不用重启，见 5.3；
> 但视觉级分带揭示因与刷新键全刷冲突暂未启用，见预研报告第九节。

**r23 结论：独立库模式下必须二选一，同时打开不会让两套效果叠加。**

原因是 HWC 单文件争用：原厂显示库 `/vendor/lib/hw/hwcomposer.ums512.so` 只有一个挂载点，墨控的 GPU 显示后端（`display.gpu`）用打了补丁的 HWC + `libeinkgpu.so` 接管取帧与像素量化；翻页动画模块用另一份 HWC 接管 `Update_Display_Image`，把整屏刷新拆成 4–32 块分阶段送驱动。两者都要求这个位置是自己那一份，无法同时挂。

0.2.5-r23 把它们合并进**同一个**后端模块，模块里放三份 HWC（`hwcomposer.default.so` / `hwcomposer.idle10.so` 为墨控 GPU 库，`hwcomposer.pageanim.so` 为翻页动画库），由 `post-fs-data.sh` 按 `pageanim.master` 二选一：

| `pageanim.master` | `display.gpu` | 实际挂载 | 结果 |
| --- | --- | --- | --- |
| 1 | 任意 | 翻页动画库 | 翻页动画生效；GPU 后端的分模式算法、迟滞、触摸加速、波形动画、全刷扫过全部停用 |
| 0 | 1 | 墨控 GPU 库 | GPU 后端生效；翻页动画不生效，`service.sh` 不拉起常驻端 |
| 0 | 0 | 原厂库 | 两者都不生效 |

注意：

- **App 里两个开关都显示「已开启」时，只是配置写了 1**，不代表两份库都挂上了。`display.gpu` 的「已开启」只说明该项被请求，真正挂哪份库由开机时的 `pageanim.master` 决定。
- 切换必须**完整重启**：`pageanim.master` 是 `REBOOT` 项，`post-fs-data.sh` 只在开机时选库；热改配置只能同步 `settings.conf` 的动画参数，不会换 HWC。
- 要回墨控显示后端：关 `pageanim.master`、开 `display.gpu`、完整重启；要回翻页动画：反过来。不要只改其中一个就以为切过去了。
- 两个引擎没有做二进制融合：它们接管的是同一条调用链，当前也没有办法把 GPU 波形时序塞进翻页动画的分块流程里。本版发布说明见 `docs/releases/0.2.6-r26.md`；更细的逆向与实验记录在工作区 `doc/翻页动画模块-冲突分析与共存方案.md`（不随仓库发布）。

### 5.1 「白名单应用走翻页动画、其余应用走 GPU 后端」为什么现在做不到

按应用分流本身是**翻页动画已有的语义**：`pageanim.readers` 名单命中、且 `a5pro-resident` 已把控制字写进注入段时，整屏刷新才被拆成 4–32 块分阶段揭示；其余帧直接放行。但「放行的那一支」是原厂逻辑，不是墨控的 GPU 后端。把另一支换成 GPU 后端有两种做法，都不属于配置层能解决的范畴：

1. **运行时按前台应用换挂载的 HWC**：不可行。Magisk 在开机 `post-fs-data.sh` 阶段决定挂哪份库，composer HAL 开机时把 `hwcomposer.ums512.so` `dlopen` 一次并完成重定位；之后改挂载文件不会改变进程里已映射的代码，只有重启 composer / SurfaceFlinger 或整机才会重新加载。每次切应用都重启显示 HAL 会黑屏闪烁、明显卡顿，且 `a5pro-resident` 依赖的 composer pid 与注入段地址（库基址 + `0x6804000`）会失效、武装状态丢失。
2. **合成一份同时含两种能力的 HWC**：这才是真正的共存，但属于二进制级改造。要把翻页动画的 `0x6800000` / `0x6804000` 两段与墨控的 `0x6300000` / `0x6310000` 两段并进同一份库（program header 扩容、PHDR 表迁移），在 `0x92fe4` 处按控制字的武装状态分流到「分块揭示」或「GPU 波形」；或改为在 `libeinkgpu` 源码里重实现分块揭示。两条路都要重新处理私有 HWC 输入、重跑开机与显示回归，而 composer 是开机必经进程，改错会黑屏甚至无法进系统。收益与风险不成比例，本版不做。

另外，**「翻页动画不主动发起刷新」并不解除争用**：它不必自己造一次 GC16，但仍必须占住 `0x92fe4` 这条传输调用才能把别人发起的整屏刷新拆块；GPU 后端改的也是这条指令（外加另外 34 个 hook 点）。刷新键走的是面板级 `clear ghosting`，两者都拦不到。

折中做法是保持二选一：翻页动画开启期间，非白名单应用仍可使用不依赖 GPU 后端的功能（自动刷新、体感、锁屏主题、桌面、字体、`display.apps` 每应用模式等，见第三节），只是分模式算法、迟滞、触摸加速与波形动画会停用。

### 5.2 后续：把冲突从「文件级」降到「源码级分支」

2026-11-08 的上机验证把上面路线 2 的后半段推进了一步：**不必合成 HWC**。
把「分块揭示」重写成 `libeinkgpu` 里 GPU 波形的条带相位后，两个引擎共用同一份
`hwcomposer.ums512.so` 与同一条 `hookUpdate` 调用链，冲突降为同一份源码里的两个
属性门控分支，不再有第二份挂载文件、也不再争 `0x92fe4`。三个要点：

- 门控改用墨控自己的 `ctl` 语义（`+0x15c` mode、`+0x160` total、`+0x2c8` region、
  `localFrame = total - remaining`），不再引用第三方注入段的 `base+0x9c2358`；
- 不重复调用原厂提交入口 `base+0x95dc4`，因而不打乱 ring 计数与波形时序；
- 真正产生分块效果时在 `gpuBeginWave(request)` 之前按条带把 `gpuIndices` 置中性，
  是纯数据操作，不改 `ctl`、不碰传输函数、不需要重启显示 HAL。

代价是第三方翻页动画库的注入段与 `a5pro-resident` 无法直接复用，分块揭示必须由
墨控 GPU 波形层重新实现。实现骨架与验证清单见 `docs/翻页动画4块原型预研.md` 第七、八节；
当前仍只是默认关闭的观测骨架，未改变显示行为。

### 5.3 0.2.6-r26 融合模式：运行时共存 + 视觉级分带揭示

- `post-fs-data.sh`：`display.gpu=1` 时优先挂 GPU HWC + `libeinkgpu.so`；
  `pageanim.master` 不再决定挂载，只有 GPU 后端关闭时才挂翻页动画专用库。
- `service.sh`：GPU 库存在时不拉 `a5pro-resident`（那份注入段不存在，拉起只会空转）。
- `ic_properties()`：两个开关都为 1 时把 `pageanim.style/bands/spacing/reverse`
  下发为 `debug.inkcontrol.fusion.*` 属性，`inkctl apply` 即时生效；`pageanim.master` 为 `HOT`。
- `libeinkgpu`：用波形层原生的分带通道（`bandDirection` + 新增 `bandRows/bandTail/bandStyle`）
  实现分阶段揭示，不需要第二份 HWC、不重复调用 `base+0x95dc4`、不改 `ctl` 矩形。

上机（**不重启**）：开机后把 `pageanim.master` 从 0 改 1，`/proc/uptime` 连续、
HWC 仍是 `a95b9f92…`、`pageanim_resident` 为空、融合属性全部下发；
触发整屏刷新出现 `FUSION_DRIVE dir=1 style=0 rows=60 tail=9 active=38 total=48`，
同期 `EinkGPU MODE_SEEN / PRE_VERIFY` 仍在，`gpu_errors=0`、composer pid 不变。
再把开关改回 0，驱动日志消失，同样没有重启。

**「刷新不干净」的修复**：分带只延后启动、不延长总帧数时，后启动的带会在 LUT 尾部
被截断，像素停在中间灰阶 → 旧页浅灰残影。现在总帧数取 `active + bandTail + 1`，
并在 frame 0 之后给原厂 `ctl` 的 `remaining/total` 同时加 `bandTail`，让每条带都跑满
整条 LUT；失败时 `restoreTail()` 撤回。代价是整屏刷新多 10~17 帧（几十毫秒）。
根因与参数见 `docs/翻页动画4块原型预研.md` 第十节。

**触发范围（白名单闸门）**：融合模式没有常驻端读触摸，所以恢复原版的第二层判据 ——
只有前台应用在 `pageanim.readers` 名单里才播放。system_server 侧在每次前台切换时比对名单，
把结果写进 `debug.inkcontrol.fusion.reader`，composer HAL 侧据此门控；名单留空即完全不触发。
这样唤出快捷面板、在非阅读器应用里滑动、打开新页面都不再播放。
同一白名单应用内的滚动/弹窗仍会播放，因为融合层拿不到手势；`pageanim.touch`、
`pageanim.keys`、`pageanim.debounce` 只在独立库模式生效。详见预研报告第十一节。

**仍要注意**：`screencap` 只能看到 Android 合成层，判断残影/黑屏要看物理屏；
分带揭示的观感与第三方引擎不完全一致（它拆传输调用，这里拆波形相位）。
