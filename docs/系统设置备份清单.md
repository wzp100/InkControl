# 系统设置备份：候选清单（待选定范围）

目标机型 HLTE203T（海信 A5 Pro 经典版，Android 10）。以下数字都是在真机上现抓的，
不是估算。**这一份只是候选清单，还没有写实现**：等你圈定范围后再动手。

## 为什么不能像「数据备份」那样整体覆盖

Android-DataBackup 那类工具是按应用整包搬 `/data/data/<包名>` 的。
它把「系统设置」理解成 `com.android.settings` 这个应用的数据目录，恢复时整包盖回去，
于是踩两个坑：

1. **prefs 里存的是「上次停在哪个设置页」以及配套的资源/键名**。恢复出厂后系统版本、
   已装应用都变了，`TopLevelSettings.onCreate` 里 `findPreference("...")` 拿不到对象就直接
   `setOnPreferenceClickListener` → 空指针 → 一开就闪退。这和本机已经踩过的
   「`com.hmct.healthyscreen` 被禁用导致设置闪退」是**同一个崩法**（实测：`pm enable` 后连开 5 次 0 FATAL）。
2. **文件属主与 SELinux 上下文**。整包盖回去常变成 `root:root` 或错误的 `u:object_r:app_data_file`，
   `system_app` 读不到自己的 prefs，同样是启动即崩。

所以墨控的做法是**逐条回放，不覆盖文件**：读的时候把每个键值抽成文本清单，
恢复时用 `settings put`、`pm grant`、`cmd appops set` 一条条写回去。
好处是能实时看到哪一条失败、失败不影响其它条，而且不需要重启。
坏处是列表型数据（WiFi 密码、蓝牙配对）没法逐条重放，只能整文件替换 + 重启对应服务。

## 一、系统设置表（settings）

真机上有三张表，合计 **417 条**：

| 表 | 条数 | 主要来源 |
| --- | --- | --- |
| `settings_system` | 160 | android 64、媒体 22、设置 18、SystemUI 18 |
| `settings_secure` | 103 | android 72、SystemUI 22 |
| `settings_global` | 154 | android 82、设置 17、海信平台 8 |

覆盖的日常项（真机实际存在的键）：

- **显示与息屏**：`screen_off_timeout`（自动息屏时长，当前 30 分钟）、`sleep_timeout`、
  `double_tap_to_wake`（双击唤醒）、`wake_gesture_enabled`、屏幕亮度与自动亮度、
  `current_epd_mode`（当前刷新模式）、`epd_*`（墨水屏参数）
- **锁屏**：`lock_screen_show_notifications`、`lock_screen_lock_after_timeout`（锁屏后多久要密码）、
  `lock_screen_allow_private_notifications`、`lockscreen_wallpaper_path`、
  `lock_screen_owner_info_enabled`、指纹/人脸解锁相关、`power_button_instantly_locks`
- **声音**：各通道音量（`volume_music` / `volume_voice` / `volume_alarm` …）、
  铃声与通知音的 URI、勿扰、`lockscreen_sounds_enabled`、`screenshot_sound_enabled`
- **输入与语言**：`default_input_method`（默认输入法）、输入法子项、语言与地区
- **网络**：WiFi / 蓝牙开关状态、`wifi_repeater_ssid` / `wifi_repeater_pwd`（海信热点中继）
- **通知**：通知灯、`enabled_notification_listeners`、`notification_sound`
- **开发者选项**：`development_settings_enabled`、动画缩放三件套、ADB、指针位置
- **无障碍**：`enabled_accessibility_services`、`accessibility_shortcut_*`
- **海信定制**：`hmct_eye_protect_status`（护眼）、`hmct_game_mode`、
  `system_settings_current_font_name`（当前字体名）

**恢复方式**：`settings put <表> <键> <值>` 逐条写入，已实测（`system` / `global` / `secure`
都能写，`su` 下无需额外授权）。
**风险**：低。但有两类键必须过滤：
① 纯设备状态的键（`has_update_package`、`next_alarm_formatted`、`notification_path`），
恢复只会让状态短暂错乱；② 指向已卸载应用的键（`media_button_receiver` 之类），写了也没用。

## 二、WiFi（含密码）

- 来源：`/data/misc/wifi/WifiConfigStore.xml`（3 KB）
- 内容：已保存网络 + **明文密码**（`PreSharedKey`），本机 1 个网络
- 另有 `/data/misc/wifi/softap.conf`（个人热点配置）
- **坑**：同一个文件里有 `<Integrity>` 段，是加密校验（`EncryptedData` + `IV`），
  密钥与恢复出厂前的设备绑定。整文件盖回去，校验对不上时 wifi 服务可能整段丢弃配置。
  恢复时需要**去掉 Integrity 段**或替换后立即 `svc wifi disable && svc wifi enable`。
- **风险**：中。恢复后第一次连网可能要重新输密码（企业级 WiFi 的证书另说）。

## 三、蓝牙配对

- 来源：`/data/misc/bluedroid/bt_config.conf`（3.4 KB）
- 内容：已配对设备（本机 4 个），含链路密钥
- 恢复：整文件替换 + 重启蓝牙（`cmd bluetooth_manager disable/enable`），或直接重启
- **风险**：中低。设备换了耳机固件可能仍需重新配对

## 四、应用权限（运行时权限）

- 来源：`/data/system/users/0/runtime-permissions.xml`（84 KB）
- 内容：**58 个包、875 条权限、635 条已授予**。按权限统计前几名：
  读写存储 301 条、位置 132 条、读电话状态 69 条、相机 51 条、录音 44 条、
  通讯录 33 条、后台位置 31 条、账户 25 条、拨号 19 条
- **恢复方式**：`pm grant` / `pm revoke` 逐条回放（已实测命令可用；对没声明该权限的包会报
  `has not requested permission`，按正常失败记一笔跳过）
- **绝对不能覆盖这个文件**：它的根节点带 `fingerprint="Hisense/HLTE203T/...:10/..."`，
  Android 10 的 `RuntimePermissionPersistence` 会校验指纹，恢复出厂后指纹不符会整份丢弃；
  更糟的是覆盖时内存态和文件态打架，权限可能大面积回退成「询问」
- **风险**：低

## 五、特殊权限与访问控制（AppOps）

- 来源：`/data/system/appops.xml`（60 KB）
- 内容：**445 个 UID、598 条 op**（允许 430、忽略 145、询问 20、拒绝 3）
- 覆盖你问的那两项：
  - **存储服务访问** = `LEGACY_STORAGE`（本机 `com.salt.music` 是 allow，`com.hmct.theme` 是 ignore）
  - **读取应用列表** = 包可见性相关的 op（Android 10 上默认不限制，海信是否有额外闸门待确认）
  - 还有：悬浮窗 `SYSTEM_ALERT_WINDOW`、修改系统设置 `WRITE_SETTINGS`、
    使用情况访问 `GET_USAGE_STATS`、通知、后台运行、`READ_DEVICE_IDENTIFIERS`、
    安装未知应用、自启动白名单
- **恢复方式**：`cmd appops set <包名> <OP> allow|ignore|deny` 逐条回放
- **风险**：低

## 六、应用的启用 / 禁用状态

- 来源：`/data/system/users/0/package-restrictions.xml`（63 KB）
- 内容：409 个包，其中 **24 个组件被禁用**
- **风险：高**。这一项就是「系统设置闪退」那类事故的来源：把系统必备组件恢复成禁用，
  重启后直接开不了机或者开不了设置。建议**只备份、恢复时逐条给人看**，
  或干脆只支持「重新启用我禁过的那些」（反方向，安全得多）

## 七、默认应用（角色）

- 来源：`/data/system/users/0/roles.xml`
- 内容：桌面（`com.hmct.vision`）、浏览器（`mark.via`）、拨号、短信、助手
- 恢复：`cmd role add-role-holder` / 桌面用 `pm set-home-activity`
- **风险**：低（恢复成不存在的包会被系统忽略）

## 八、通知策略

- 来源：`/data/system/notification_policy.xml`（46 KB，79 个包）
- 内容：每个应用的通知开关、通知渠道、免打扰规则、勿扰时间表
- 恢复：`cmd notification` 能力有限，多数只能整文件 + 重启
- **风险**：中。整文件恢复后没重启的话，NotificationManagerService 内存态与文件不一致

## 明确不做的

| 项 | 原因 |
| --- | --- |
| `packages.xml`（2 MB） | 含签名摘要、UID 分配、安装时间。恢复会与已装应用对不上，`system_server` 直接崩 |
| `locksettings.db` | 锁屏密码/PIN 的哈希。恢复后自己都解不开 |
| `settings_ssaid.xml` | 每台设备的 ANDROID_ID，恢复会让两台设备撞 ID |
| 账号（`/data/system/users/0/accounts*`） | 存的是 token，跨设备恢复有安全风险，且大概率失效 |
| 各应用自己的 `/data/data/<包名>` | **这正是 DataBackup 崩掉的那一类**，跨版本恢复必然 schema 不匹配 |
| 字体文件 | 已经有 `inkctl applyfont`，走原路 |
| 壁纸 | 已经在 `wallpaper_orig`，会话里另有入口 |

## 建议的默认勾选（我的意见）

真正值得备份、又能安全回放的，是这四组：

1. **系统设置表**（息屏时长、锁屏时长、音量、输入法、字体名、护眼……）—— 417 条，逐条回放
2. **网络**：WiFi 密码 + 蓝牙配对 —— 整文件替换 + 重启服务
3. **应用权限**：运行时权限 + AppOps —— 逐条回放
4. **默认应用** —— 角色回放

**禁用组件**只做「查看 + 单向重新启用」，不做还原成禁用；**通知策略**先不做（回报太低、坑多）。

## 还有一件事：备份到哪

- 存 `data/adb/inkcontrol/backup/<时间戳>/`，root 可读写、不会被「清除应用数据」带走
- 每次备份写一份 `manifest.txt`：时间、机型指纹、每项条数与 sha256
- 恢复前自动存一份 `pre-restore/` 快照，出问题能一键退回
- 是否要能导出到 `/sdcard` 做成 ZIP 给人拷走，看你要不要跨机型用
