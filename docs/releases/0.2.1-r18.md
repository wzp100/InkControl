# 墨控 InkControl 0.2.1-r18

面向 **Hisense A5 Pro 经典版黑白屏**的候选预发布。本版在 0.2.0-r18 基础上重做锁屏「拓展显示」、新增系统应用卸载/还原入口、新增「控制中心拓展」、放大功能列表的分区小标题、重排瑞士网格版式，并把构建输出从 613 MiB 压到 169 MiB。**73 个增强全部默认关闭**（「设备状态」的四项显示开关除外，它们默认开启）。

版本号按仓库规则升为 0.2.1-r18：本版含配置键删除（`lock.ext.*` 四项合一后又按新语义恢复为四个显示开关）与新的后端命令，必须新版本，不覆盖 r18 的 Release。

## 锁屏「拓展显示」

- 「锁屏-通知」改名为「拓展显示」，由原先四个逐项开关精简为**两个总开关**：`lock.notify`（显示通知）与 `lock.ext`（显示设备状态）。
- 两者**严格二选一互斥**：开一个自动关另一个，互斥实现只在 `MainActivity.change` 一处，列表开关与详情页按钮走同一条路径；关对方时沿用其现值（`lock.notify.value=system|wechat`）。
- 设备状态条占原通知条位置（逻辑 y 613、高 42），显示**无线网络、蓝牙、声音模式、飞行模式**四项，取值实时读 WifiManager、BluetoothAdapter、`AIRPLANE_MODE_ON`、`getRingerMode()`。
- 图标用矢量 Path 现画（16×16 逻辑框：三段同心弧+圆点、卢恩字母 Bjarkan、实心喇叭+声波、俯视飞机），**不引外部图片**——墨水屏只有黑白，矢量在 2 倍放大下仍是硬边，也不必为第三方图标库背许可证与体积。
- 对齐按「墨迹」而不是方框：四个图标的墨迹纵向范围各不相同（wifi 天生扁、飞机最高），逐个等比缩放到同一墨迹高度并把墨迹中心压到文字视觉中线（基线上方 5px），四格看上去才是齐的。状态文字统一 13sp 加粗，声音项显示「有声」/「静音」。
- 实心图标（声音、飞行）目标墨迹高度单独提到 12.8 / 13.2：按墨迹等高归一后，实心图形比同高的细线图形视觉重量小，等重反而显小。
- 图标形状按 1-bit 量化效果定了三条硬约束：喇叭的声波弧必须画在正右半圆（`arc` 起始角 -45°，原来固定 225° 会画到喇叭头顶上）、飞机翼展要明显大于机身长（15 × 12.2，比例低于 1.15 就退化成十字）、平尾只有翼展一半宽。
- 状态条**会自动在单行与 2×2 之间切换**：竖版 312 宽单行四格（每格 78）；横版右下只有 155 宽、单格 38.75 装不下「图标 + 静音」，自动降级成 2×2，同列的图标左沿与文字左沿对齐（先按该列最宽项拼一行再整体居中），两行才不会错开。
- 旧配置 `lock.notify.value=ext` 自动迁移为 `lock.notify=0` + `lock.ext=1`；单值时代的 `lock.ext.value=default` 读成 `auto`。

## 锁屏「设备状态」：显示哪几项、画成什么样

- 「拓展显示」这一节现在只有三行：**显示通知**（开关）、**显示设备状态**（开关）、**显示信息修改**（无开关，点进去改）。原先并排铺开的四个显示开关收进「显示信息修改」一页，列表里不再出现四行小开关。
- 「显示信息修改」是纯页面项（`FeatureCatalog` 里取值写作 `@panel`，配置值恒为空串）：它自己不是开关，进去逐项开关的是 `lock.ext.*`。页首给出「N / 4 项显示 · 文字版」的汇总，下面是四行只带开关的行（点行不跳页，免得从四项详情返回时跳出「收纳」回到分类列表），末尾一个按钮跳去「显示设备状态」选图标版／文字版。
- 分类卡上的「已开启/总数」把这四项照旧算进「锁屏」（`Guide.Category.nested`）：它们仍在配置里、仍是可关的开关，只是换了入口，「锁屏」还是 16 项。
- 新增四个**显示开关**：`lock.ext.wifi` / `.bt` / `.audio` / `.airplane`，分别控制设备状态条里出现哪几项。关掉的项不占位，其余各项重新均分宽度（四项单行、三项两列上二下一、两项竖排）。这四个开关是**默认开启**的（`FeatureDefinition.defaultOn`：配置里没有这个键就按显示处理），所以老用户升级后四项仍在，之后各自关掉的才记住。
- `lock.ext` 从单值开关变为三选一：**跟随样式**（`auto`，默认）/ **图标版**（`icon`）/ **文字版**（`text`）。`auto` 时编辑排版与横版用图标，瑞士网格用文字——各样式保持原有观感。
- 文字版画成 `无线|开`：类型名与状态值**同为 13sp 加粗**、同一条基线，中间一条 1px 实心竖线（不用字形「|」，1-bit 下那根线粗细随字号变、还带侧边距）。原来瑞士网格是「类型 10sp + 状态 15sp」，一大一小既不像一组、也看不出是同一条视觉中线。
- 降级规则改为按项数通用的两列布局：任一项量不下就换两列、行数取 `ceil(n/2)`、按行优先填。原实现里 `n < 4` 会被强行塞进单行，三项时单格只有 51.7 宽，触发「极窄格子兜底」把类型名整个丢掉，只剩「开 关 开」。

## 锁屏「设备状态」在四套样式里的位置

- **编辑排版（竖版）**：倒数日下方那一块（y 613、高 42），单行四项。
- **编辑排版-横 / 编辑排版-横-逆**：右下角原通知框位置。框从 x605 / 宽 95 左移到 **x545 / 宽 155**（右缘仍与倒数日框对齐，与电量之间留出 5px），高度 40 → 48、框顶 280 → 272（框底 320 压在天气行字身顶 323 之上），电量行右界相应从 600 收到 540。逆版与正版共用同一份 `editorialLand()`，镜像由 canvas 旋转 180° 处理，无需另写。
- **像素**：先是在电池窗口**正下方另起一块**（沿用 `window()` 的老式窗口，2px 边框 + 4px 实心投影）塞四项，靠「图标在上、ON / OFF 在下」压缩宽度——该样式整体是英文标牌（CLOCK / NOW PLAYING / SLIDE TO UNLOCK），不混中文。本版末又把下半部整体重排为 **格言 → 电量 → 倒数日 → 通知/设备状态** 四块，见下节。
- **瑞士网格**：底部数据行正上方新增一条「通知带 / 设备状态带」——1px 分隔线 + 一行数据。显示通知时是「通知｜3 条」：类型 13sp、条数 26sp 黑体，两者**按墨迹中线对齐**且紧靠在一起（原来标签 10sp 贴左沿、条数 28sp 贴右沿，隔了三百像素，既远又不在一根视觉轴上）。显示设备状态时四项均分整条 320 排「无线|开」这类文字标牌，类型与状态同字号同基线、中间 1px 竖线；该样式通篇没有图标语汇，所以只用文字版。带子顶**固定在 586**（钳位 586–594），不跟格言块底边走——跟着走时格言正文加译文一长就贴上去。
- **液态玻璃**：底部是单行紧凑文本位，放不下四项，本版未适配，仍按通知位显示。

## 像素（竖版）版式：格言 → 电量 → 倒数日 → 通知/设备状态

- **为什么要重排**：原来通知数与电量同挤一行右端，设备状态块只能挂在电量正下方，读起来像「电量的附注」；而通知与设备状态本就是同一个位置的两个互斥总开关。现在电量独占一块，通知与设备状态**共用最后一块**：同高 58、标题分别是 `NOTIFY` / `STATUS`，来回切总开关时整摞块不会上下跳。
- **块高与间距**：电量 48、倒数日 80（无倒数日时整块不画）、状态槽 58（通知与设备状态都不显示时整块不画）。间距按 `(H-58-12-top-stack)/块数` 在 **12–22** 之间取值——最坏情形（格言 3 行 + 曲名 + 进度条、倒数日 3 组）仍停在 y 628，离底部解锁框（y 662）还有 34，绝不会压框。
- **电量块**：电池图标 scale 3（墨迹 24 高，中线压在块中线），内腔按电量从左填充、宽度取 3 的整数倍以落在物理像素上；百分比提到 **u=2.5**（一格 5 物理像素）撑起这块的视觉重量；充电时右端补一个 u=1 的 `CHARGING`，不充电就留白，不塞无意义装饰。
- **倒数日块**：`COUNTDOWN` 标题下每列「事项名 / N DAYS」，列宽分配与竖版一致（1 组居中、2 组 1/4 与 3/4、3 组 1/6 3/6 5/6）。天数是主要信息，走 5×7 点阵（u=1.5，1-bit 下比黑体干净），**已过用负号**（`-3 DAYS`）；事项名是中文，只能交给无抗锯齿黑体 16sp，超长按列宽横向压缩，不串邻列；没填事项时只画天数并在内容区里居中。
- **通知/设备状态块**：设备状态沿用四项「图标（墨迹 11 高）/ ON|OFF（u=1.5）」，比原来的 13 收小一档——有了标题栏，内容区只剩 32 高；通知则是 `NOTIFY` + 图标 scale 2 + 数字 u=2.5 + 中文来源名（`通知` / `微信`，那是数据不是标签，不译成英文）。

## 瑞士网格（竖版）版式调整

- **表头固定三列，字号 12 → 14**：`周三 第44周` / `10.29 | 9.20(农历)` / `2026年 | 第302天`。原来第一列「周三 WED」的英文星期换成年内周数，第三列年份后补「第 N 天」，这两项原本挂在右缘竖排里。农历用 `LunarCalendar.toLunar()` 现算成 `月.日`（系统 `Lunar` 只给「九月十八」这种中文，排不进 101 宽的格子），后面跟一个 **12sp** 的 `(农历)` 注释——注释不能按统一基线挂：小一号的字形框是等比缩的，挂同一基线会矮下去一截像角标，所以 `segRow` 改成按**字形框中线**对齐各分段。三格等宽但字数差得远——14sp 的「2026年 | 第302天」要 107 宽、塞不进 101.3——所以取三格里最小的比例**统一缩放**（实测落到 13.3sp）：只缩塞不下的那一格会让表头字号参差。段内不做横向压缩，那会把数字压瘦变形。
- **两行大时间：横向松、纵向贴**。字距保持 **+0.06em**（两位数字能看出间隔）；两行基线 188 / 360 时墨迹间隙实测 **47**（设备像素 94），实机看是两根互不相干的横条，用户要求按现距离收到 1/3，现在 **188 / 329**、间隙 **16**，两行归成一个整块。行距按实测留：184sp 数字墨迹只有 **125** 高（0.68 倍字号，不是 0.77），墨迹下沿即基线。
- **右缘竖排整列删除**：`第 N 天` 与 `第 N 周` 搬进表头后这一列没有内容了，右缘留白。原先是 13sp、步长 17、中间留一个空槽的竖排，逐字下排还会把「301」拆成 3 / 0 / 1 读成「三〇一」——整列去掉反而干净。
- **天气块固定留位 352–428**：不管有没有数据都占住这一段，格言分隔线定在 **428**、格言恒为 2 行。原来没天气时格言直接顶到第一个可用位置，天气数据一回来整摞内容就往下跳一格；模块设置里没开天气显示，所以留白才是常态。
- **格言下方补当前曲目行**：播放媒体时在格言正文下 7px 起画一行 `— 曲名 · 歌手`（12sp、单行、超宽横向压缩），与上游瑞士风格一致——左边那两行 `NOW PLAYING` / `DAILY QUOTE` 只是栏目标签，曲名必须单独成行才读得到。
- **设备状态带 15sp → 17sp（按宽度自适应 16/17）**：用户反馈还是偏小。四项不再按「74 + 8」的格排，改为**均分整条 320**（每格 80）。17sp 时最宽的「声音 | 静音」是 34 + 5 + 1 + 5 + 34 = 79，4 项均分每格 80——能塞下但与邻项只隔 1px，实机看着像「静音飞行」连成一串；所以画之前先量一遍，塞不下就整行退到 16sp（75 宽，留 5px），3 项时仍是 17sp。
- **纵向重新分配：底部往屏幕底下靠、格言与设备状态带拉开**。底部横线 620 → **646**，最低的「电量 %」标签基线落到 **690**，离屏幕底沿只留 30（原来 76，看着悬在半空）。带子原先「跟着格言块底边走」，但格言正文 2 行 + 英文译文 2 行时块底会落到 521，带子跟着走就只剩 28 的空白，实机看着贴着（预览样张里格言只有一两行，所以显得远）；于是把**带子顶固定 586**（基线 616、文字墨迹底 618），格言块底到带子留 **65**，带子到 646 的横线还剩 27。钳位 586–594 只是安全阀，格言异常长时最多下移 8。为把这点空间腾出来，天气留位与格言线同时上提 24（376–444 / 456 → **352–428 / 428**）。
- **底部「电量 + 倒数日」再排一次**：`↑ 解锁` 整行删除，右端 340 全部让给倒数日。「倒数日」标签由 10sp 横排改成 **14sp 竖排**（电量占 20–94，标签列心 104），既跟 30sp 的电量、14sp 的事项名成比例，又正好当两者之间的一条竖排分隔；倒数日各列从 118 起排到 340，每列「事项 14sp / 剩 N 日 13sp」，居中规则与「编辑排版」竖版一致（1 组居中、2 组 1/4 与 3/4、3 组 1/6 3/6 5/6），事项为空时天数单行居中。分隔线 **fy = 646**。

## 系统应用卸载/还原

- 首页新增独立分类「系统应用卸载/还原」，排在「系统增强」之前，独立页面不走功能列表。
- 预制两项：`com.hmct.updater`（系统更新）、`com.tencent.android.location`（腾讯位置服务）。后端新增 `inkctl sysapp state|remove|restore`，包名双重正则校验，只对 user 0 卸载；`pm install-existing` 还原后仍是系统应用身份，系统分区 APK 不会被删。

## 控制中心拓展（`qs.extend`）

- 现象：下拉快捷设置的「编辑磁贴」页里只有海信自家磁贴，装了磁贴的第三方应用（Syncthing Fork、Xplore、Appzuku、Obsidian、LocalSend…）**一个都不列**；但这些磁贴本身可用——手动把 `custom(包/服务)` 写进 `sysui_qs_tiles` 后，面板上正常显示与工作。所以限制只在「候选列表」这一层。
- 根因：`TileQueryHelper.queryTiles(QSTileHost)` 只有两行实质逻辑——`addCurrentAndStockTiles(host)`，然后
  `if ("true".equals(SystemProperties.getStable("stable.sys.runtimepregrant", "false"))) addPackageTiles(host);`。
  `addPackageTiles` 内部是**完全原厂**的 `queryIntentServicesAsUser` + `CustomTile.toSpec`，没有任何包白名单；所谓「白名单」就是这个 if。
  而 `getStable("stable.sys.runtimepregrant")` 被海信改写成读 **`ro.hx.test`**。
- 为什么不能靠改属性绕过：`ro.hx.test` 同时是海信的**安全特性总开关**——`android.safe.SafeFeature.<clinit>` 里
  `RUNTIME_ENABLE = getBoolean("ro.hx.test", false)`、`ENABLE = persist.sys.hmct.safe.enable && !RUNTIME_ENABLE`，
  置真会把 `AUTORUN / CTA / PAY_GUARD / SAFE_NOTIFY` 连同定制锁屏键盘一起关掉，锁屏退化成 AOSP 原生样式（「请输入数字密码」+ 对勾、无指纹捷径）。实测踩过一次，已回退，**这个属性不要碰**。
- 实现：模块作用域本来就有 `com.android.systemui`，在 `queryTiles` 的 after 里反射调一次原厂私有 `addPackageTiles(QSTileHost)`。它自己 post 到 `mBgHandler` 查询、逐个走 `addTile`（`mSpecs` 去重）、最后 `notifyTilesChanged` 把完整列表推给编辑页，所以顺序、去重、分组全部沿用原厂，模块只补「少掉的那一次调用」。
- 生效范围与时机：只影响「编辑磁贴」的候选列表；判定读 `RuntimeConfig`，**每次打开编辑页重新判断**，改开关不用重启，也不用重启 SystemUI。关闭时完全等同原厂（一行额外的代码都不跑）。
- 验收（本机 HLTE203T）：关闭时「拖动可添加快捷开关」只有 **5 个**原厂磁贴（投射屏幕、时钟、超级省电、计算器、WLAN信号桥）；开启后同一位置变成上百个，末尾是 `Open Obsidian / Daily Note / Search / New Note / LocalSend / 发送剪贴板 / Color Picker / Tile 1–9 / 一键冻结` 等第三方项，`WLAN热点 / USB网络共享 / 蓝牙网络共享` 这类由海信系统应用以 `TileService` 形式提供的磁贴也一并出现；关掉开关再开一次编辑页，列表回到 5 个——双向切换都不需要重启。
- 顺带修掉的两个界面问题：列表内的导航卡（「原厂四模式 · 算法」四张、字体、「显示信息修改」）自带圆角 14 的框，叠在分组列表圆角 12 的描边上会看成「方框里套扁圆框」，改为常态透明、按下才描边；「编辑排版-横」正版把竖排「上滑解锁」从画布左端移到右端（竖屏面板上原本落在顶边、横转后是屏幕最左），内容右界 `R_END` 随之 700 → 668，「-横-逆」不变。

## 界面

- 「大功能」内各功能列表的分区小标题（「样式」「拓展显示」「倒数日」「触发方式」「节奏」等）由 14sp 普通字重放大到 **21sp 加粗**，相对页标题 26sp、功能名 17sp、说明 13sp 形成清晰层级。
- 「自定义锁屏」页的**效果大图移到样式列表之后**（「需要知道」之前）：那一页真正的选项是带缩略图的样式列表，大图放上面会先占一屏。大图与缩略图的样张同时跟随「显示设备状态」——开着时画状态条而不是通知框，避免出现「开关开了但预览还是通知」的错觉。
- 大功能排序新增分类不再一律追加到末尾：保存顺序里没有的分类插到默认顺序中它前一个已排好分类之后。
- **「编辑排版-横」的竖排「上滑解锁」移到屏幕最右**：原来这一列画在横版画布左端（x=12），竖屏面板上落在顶边、手机横转阅读时正好是屏幕最左，与「摄像头—时间—倒数日—上滑解锁—充电口」的顺序相反。现按版本分向：正版落在画布右端（x=692，横转后即最右），「-横-逆」保持画布左端（整幅再转 180° 后同样在面板最右）。正版内容右界随之从 700 退到 668（表头、时间方框、倒数日框、通知框、天气行同步收窄），给解锁列让出 24；逆版内容右界仍是 700，出图与改动前逐像素一致。
- **分组列表里的导航卡片不再叠双层描边**：「原厂四模式 · 算法」的四张算法卡、字体、「显示信息修改」都走 `navCard`，自带一圈圆角 14 的框；外层分组列表已经有圆角 12 的描边，两层半径不同，直边叠成 4px 粗线、四角错开，看着像「一个方框里套了个扁圆框」。改为与普通功能行同一套处理：常态透明露出分组描边，按下时用圆角 12 的加粗框。模块页里单独摆放的导航卡（安装/诊断/排序等）仍保留自己的框。

## 开发工具

- 新增 `tools/IconPreview.java`：用与 `LockCanvas.drawIcon` 相同的 16 空间坐标绘制四个图标，再按「面板 2 倍 + 1-bit 阈值」二值化输出，3 秒就能判断图标在墨水屏上是否可辨，不必每改一处形状就装一次机器。

## 构建与产物

- 逐段中间文件从 `out/<name>/work/` 移到 `out/.work/<name>/`，**构建前后各清一次**：即使收尾清理失败，下一次构建开头也会整体清空，不再每个版本攒一份 13 MiB 的 `work/`。
- 用完即弃的中间产物立刻释放（`module/`、`classes/`、`classes.jar`、`unsigned.apk`、`normalized.apk`），`--keep-intermediates` 时全部保留。
- 新增 `--clean`（只清理不构建）、`--keep-builds N`（产物目录只留最近 N 个，默认 3）、`--cache-budget M`（构建缓存上限，默认 160 MiB，按「最久没命中」淘汰；命中会刷新时间戳）。
- 实测：`out/` 由 613 MiB 降到 169 MiB（34 个产物目录 → 3 个，缓存 250 MiB → 159 MiB），单个产物目录只留 APK 2.10 MiB + 后端 ZIP 1.03 MiB + 清单/证书/校验和。
