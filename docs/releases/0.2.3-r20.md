# 墨控 InkControl 0.2.3-r20

面向 **Hisense A5 Pro 经典版黑白屏**的候选预发布。本版重写「快捷面板修改」的动作选择：四个位置的选项里补上墨控自己的三个开关、最顶上的「无」和最底下的「App…」，并给 WiFi／蓝牙／墨控三项加长按跳设置；原厂「截屏便签」的图标文字可以缩到与补上来的按钮齐平；修好一直报「省电模式切换失败」的那一格，按钮提示也回到屏幕默认的底部位置。**82 个增强全部默认关闭**（「设备状态」的四项显示开关与「截屏便签对齐尺寸」默认开启）。

版本号按仓库规则升为 0.2.3-r20：本版下线 `qs.pinlaunch`、新增 `qs.panel.pinsize`，并给四个位置的取值加了 `none` 与单包名类型，旧后端不认这些键，必须同批重装后端。

## 「截屏便签位置」并入动作表

- 原来单独一行的「截屏便签位置」（`qs.pinlaunch`）整项下线，它那四种去处不再单独配置：四个位置现在共用同一套动作表，其中 **`pin` 就是原厂「截屏便签」**（图标、文字与原厂截屏监听器原样保留）。要隐藏这一格就在对应位置选「无」，要换成墨控或别的应用就选「App…」。
- 分类里当时只剩「按钮」一个小节、一个入口，中间那层列表没有内容。**首页点「快捷面板修改」现在直接进「快捷面板按钮」详情页**（四格编辑器、总开关、两个页内开关都在这一页），返回直接回大功能列表，不再经过只有一行的中间页；`点完收起面板` 与新的 `截屏便签对齐尺寸` 都是收在这一页内的开关行，**没有「›」、点行不跳说明页**。
- 旧配置里的 `qs.pinlaunch` 会在 App 侧与后端两侧同时按遗留键放行，不会导致整份配置被拒。

## 四个位置的选项

- 动作表在控制中心那十个磁贴（WiFi、蓝牙、铃声、飞行模式、手电筒、自动旋转、整屏翻页、免打扰、省电模式、悬浮球）之外，补上 **`自动刷新`、`锁屏主题`、`遮挡息屏`** 三项：点一下就地开/关 `refresh.master`／`lock.style`／`wave.lock`，图标与文字同步。系统界面没有墨控私有目录的写权限，这三项经 `content://com.inkcontrol.state` 的 `toggle` 接口交给应用进程写盘并应用，接口只放行这三个 id。
- **最顶上是「无（这个位置不显示）」**：这一格不生成按钮，后面的按钮自动往前挪，`InkButtonsParent` 按剩余个数重新均分宽度。
- **最底下是「App…」**：点进去是和「自动刷新 · 黑白名单」同类的应用选择界面，带搜索框，**应用名和包名都能搜**（有些应用显示名一样、包名不同，所以每行把包名也列出来），列表额外补上墨控自己。选中的包名直接存进该位置的取值。
- 顺序仍靠「两格动作对调」，不另存顺序键；「恢复默认顺序」回到 WiFi · 蓝牙 · 墨控快捷设置 · 截屏便签。

## 长按跳设置

- **WiFi / 蓝牙** 长按跳原厂的 Wi‑Fi／蓝牙设置页。
- **自动刷新** 长按跳墨控的「自动刷新」**大功能分类页**（整组触发方式、节奏、应用名单都在那一页），**遮挡息屏** 长按跳「体感」大功能分类页；两者带分类名从面板进来，不再停在「自动刷新总开关」「遮挡息屏」某一项的说明页。分类名取功能目录里的 `group`，与首页卡片同名，且只放行真实存在的分类。
- **锁屏主题** 长按仍跳样式选择那一页（走桌面快捷方式通道），因为那一页本身就是要找的选项列表。
- 长按**一律先收起面板**，不给开关：面板是盖住下半屏的悬浮窗，跳过去还盖着就没意义。其余动作（铃声、手电筒等）没有对应设置页，长按不响应。
- 点击仍是原来的开/关动作，不受长按影响。

## 原厂「截屏便签」对齐尺寸

- 原厂那颗按钮按整块面板的尺寸画，图标和文字比补上来的大一圈。新增 **`截屏便签对齐尺寸`**（`qs.panel.pinsize`，默认开）：按同样的 28dp 图标、12sp 文字重画，只改尺寸，不碰文字内容、图标和原厂监听器，四个按钮看起来齐平。关掉就恢复原厂大小。

## 省电模式修复

- 海信的「省电模式」不是 AOSP 的 Battery Saver：状态在 `Settings.System` 的 `powermanager_mode_common`，开关由 `com.hmct.powermanager` 收 `INTO_COMMON_MODE_NEW` / `EXIT_COMMON_MODE_NEW` 广播去做。之前调的是 `PowerManager.setPowerSaveMode`，这台设备没有那条路径，每次都抛异常并提示「省电模式切换失败」；现在改成按原厂状态键判断目标状态、发对应广播。

## 按钮提示回到屏幕底部

- 面板是盖住下半屏的系统悬浮窗（`type=0x7d9`），层级比 Toast（`0x7d5`）高一层。早先的实现因此把提示用 `Gravity.TOP | CENTER_HORIZONTAL` 固定在**距屏幕顶部 72dp**处，免得被面板压住。
- 这一版改回**系统默认位置（底部居中）**：删掉 `setGravity` 与 72dp 偏移，同时把点击流程改成**先收起面板、再弹提示**——`click()`（WiFi、蓝牙、铃声等）与墨控三项的 `toggle()` 都调了这个顺序。
- 默认开着「点完收起面板」，面板先撤走，底部提示就不会被压；**关掉该开关时面板仍在**，底部提示会被面板盖住，这是系统窗口层级决定的，不是回归——想看到提示就保持那个开关打开。
- 提示文案不变，仍按目标状态写（`蓝牙已打开` / `蓝牙已关闭`），请求没被受理时照旧提示失败。

## 说明文字

- 「快捷面板按钮」页去掉「需要知道」区块；`点完收起面板` 的介绍与独立入口一并删除，两个开关都只是页内一行开关。其余条目保持一句话说明。

## 排障：两个无障碍服务与「依赖未满足」

- 系统无障碍里两个服务**各跟各的开关**：`refresh.master` → 「墨控自动刷新」(`RefreshService`)，`wave.lock || wave.wake` → 「墨控体感」(`WaveService`)。这条映射从 0.2.1-r18 引入起就是这样，r20 没有改 `backend/lib/common.sh` 的 `ic_accessibility()`。当前配置里 `wave.lock=0`、`wave.wake=0`，所以后端 `service.sh` 每 60 秒自愈时会把手动打开的「墨控体感」撤掉——这是设计行为，不是回归；自动刷新用的是「墨控自动刷新」，它已随总开关自动启用。
- 「自动刷新」子项显示「依赖未满足」**与无障碍服务无关**。`FeatureService.status()` 要拿父项 `refresh.master` 的运行时回执（版本、`revision`、取值、进程 pid/start 全部匹配）才放行子项；回执缺失时子项一律标「依赖未满足」，父项自己标「等待运行确认」。升级 APK 后若没重载 LSPosed 作用域，就会卡在这里，诊断页显示「框架模块 1 / 3 个作用域已加载」。
- 本轮实测：`setprop ctl.restart zygote` 软重启（不断电、无线 adb 会自动恢复）后三个作用域重新加载 0.2.3-r20，诊断页变「3 / 3 个作用域已加载」，自动刷新分类页全部变「已生效」，首页「待重启」归零。手动去系统设置里点开「墨控体感」对此没有作用，也不需要它。

## 验证范围

构建通过；电脑端 Java 侧（`CoreTest` / `GuideTest` / `TextCatalogTest` / `RuntimeStatusTest` 等）全绿，`check_docs.py` / `check_repository.py` / `check_i18n.py` 全绿。`tools/test.py` 的 Python 部分仍有仓库既有的 11 项红（`test_gpu_diagnostics` 5 项 + `test_backend` 系 6 项，与本次改动无关，本轮 `common.sh` 未改）。实机部分见下文「已确认 / 未确认」，未列出的项不做承诺：面板观感、功耗、温区与长期稳定仍待独立验收。

### 已确认（A5 Pro 经典版，HLTE203T / Android 10）

- 首页点「快捷面板修改」**直接落到按钮编辑页**，原本只有一个「按钮 → 快捷面板按钮」入口的中间列表不再出现，返回一次就回大功能列表；页内四行「序号 · 动作」、`←`／`→`、`恢复默认顺序` 与两个开关行都正常，「需要知道」不再出现；两个开关行没有「›」，点行不跳说明页。
- 动作选择框最顶是「无（这个位置不显示）」、最底是「App…」，中间依次是 WiFi、蓝牙、铃声、飞行模式、手电筒、自动旋转、整屏翻页、免打扰、省电模式、悬浮球、自动刷新、锁屏主题、遮挡息屏、墨控快捷设置、截屏便签。
- **按钮提示位置**：点「蓝牙」后「蓝牙已关闭」／再点一次「蓝牙已打开」的气泡都落在**屏幕底部**（不再是距顶 72dp 的顶部位置），面板同时收起，状态栏蓝牙图标同步变化；两次都在点击后立刻截屏核对，`dexdump` 里 `Toast.setGravity` 已不再出现。
- 首页显示 `v0.2.3-r20`、`34 已开启 / 82`、`快捷面板修改 (7/7) 已开启`，界面口径仍是 82 项。
- **「无」**：选后 `qs.panel.btn1.value=none`，面板只剩三格，宽度自动均分，没有留下空格子。
- **「App…」**：弹出带「搜索应用名或包名」的列表，每行显示应用名＋包名，最底项会回显当前应用（`App…（当前：Aurora Store）`）。按应用名 `aurora` 与纯包名片段 `com.aurora` 都能精确筛出 Aurora Store；选中后写入 `qs.panel.btn1.value=com.aurora.store`，面板该格显示它自己的图标与名称。
- **墨控三项点一下就地开关**：第 1 格设为「自动刷新」后点一下，顶部弹出「自动刷新已打开」，面板自动收起，`refresh.master` 由 0 变 1；再点一次变回 0。
- **长按跳设置**：长按「蓝牙」跳到 `com.android.settings/.Settings$BluetoothSettingsActivity`；长按「自动刷新」落到「自动刷新」大功能分类页（本轮实测，标题为「自动刷新」、含「总开关 / 触发方式」小节，不再是「自动刷新总开关」单项说明页）；长按「遮挡息屏」落到「体感」大功能分类页（本轮实测，标题为「体感」、含「行为」小节）。三次跳转面板都已先收起，没有遮挡。
- **省电模式修复**：点击「省电模式」弹出「省电模式已打开」（不再是「省电模式切换失败」），`Settings.System.powermanager_mode_common` 由 `null` 变 `1`；再点一次变回 `0`，双向切换成功，无线 adb 未掉线。
- **截屏便签对齐尺寸**：开启时第四个原厂按钮的图标与文字与前三格齐平；关掉后恢复原厂的大圆圈图标与放大文字，对比明确。
- **关掉总开关**：面板完全恢复原厂，只剩居中一个「截屏便签」，图标与文字都是原厂尺寸，没有残留装饰（0.2.3-r19 的遗留未确认项）。
- 面板底部四格横排，图标与文字完整，面板高度与原厂一致（0.2.3-r19 起已确认，本版沿用同一布局路径）。

### 未确认

- 铃声、飞行模式、免打扰、悬浮球四项只做了代码层核对，没在设备上逐一点测；「锁屏主题」的点击与长按复用同一条 `toggle` / `shortcutTarget` 通道，本轮未再抽验。
- WiFi 长按复用了与蓝牙同一条 `Settings.ACTION_*_SETTINGS` 通道，只抽验了蓝牙。
- 长时间反复唤出/收起与后台功耗。
