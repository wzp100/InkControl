# 刷新格言：从应用外面调用

锁屏那句格言由 SystemUI 里的原厂 `MottoHelper` 出图，只有 SystemUI 进程能反射到它。
所以外部不需要「打开墨控」——把下面任一条命令发过去，墨控转成一条广播，SystemUI 换下一条格言，
屏幕上只留它自己那句提示。

## 一、广播（最省事，脚本 / 自动化首选）

```sh
am broadcast -a com.inkcontrol.action.REFRESH_MOTTO -p com.inkcontrol
```

su shell、Termux、Tasker 的「发送广播」、MacroDroid 的「发送意图」都能用，不需要墨控在前台。
收到后立刻返回，没有界面。

`-p com.inkcontrol` 不能省：Android 8 起静态注册的接收器收不到**隐式**广播，不带包名会被
`BroadcastQueue` 拦成 `Background execution not allowed`，命令看起来成功了、格言却没换。
带上包名的广播算显式投递，才到得了 `MottoReceiver`。

## 二、启动透明页（墨控被「强制停止」时用这条）

```sh
am start -n com.inkcontrol/com.inkcontrol.ui.MottoActivity
```

`MottoActivity` 是透明、无历史、不占任务栈的空壳，发完广播自己 `finish()`，不会把墨控主界面拉起来。
厂商的进程管控只拦 provider / service 的拉起，不拦 `startActivity`，所以应用被 force-stop 之后
广播叫不醒它的时候，这条仍然生效（和面板开关的 `PanelToggleActivity` 是同一套思路）。

## 链路

```
外部 am / 桌面快捷方式 / 锁屏页小徽标
   → MottoReceiver（广播）或 MottoActivity（透明页）
   → sendBroadcast(LOCK_MOTTO_NEXT, package=com.android.systemui)   ← MottoCommand.request()
   → Lock Hook 注册的 receiver → MottoHelper.getNextMotto() 反射调用
   → 结果兜在 sNextMotto（10 分钟）→ 下次息屏出图优先用它
```

桌面快捷方式里的「刷新格言」现在也走 `MottoActivity`，点了只换格言，不再打开墨控。

## 前置条件与反馈

- LSPosed 作用域要含 `com.android.systemui`，模块已启用。否则广播发得出去、但没人换（也不会报错）。
- 刚安装或刚升级墨控之后要先打开一次应用：`pm install` 会把包置回 stopped 状态，静态接收器不投递广播，
  这时用第二条 `am start` 或者手动开一下墨控即可恢复。
- 成功时 SystemUI 弹「已换到下一条格言：…」；系统给不出下一条时是「格言没换成：系统没有给出下一条」。
- 换来的那条只兜 10 分钟，够锁一次屏看到，之后交回原厂自己轮换。

## 相关文件

| 文件 | 作用 |
| --- | --- |
| `src/com/inkcontrol/features/lock/MottoCommand.java` | 唯一出口，`ACTION` 常量与 `request()` |
| `src/com/inkcontrol/features/lock/MottoReceiver.java` | 外部广播入口（manifest 注册，exported） |
| `src/com/inkcontrol/ui/MottoActivity.java` | 透明页入口，桌面快捷方式也戳它 |
| `src/com/inkcontrol/features/lock/Hook.java` | SystemUI 侧真正干活的地方（`ACTION_MOTTO_NEXT`） |
