# 全刷后画面退回上一页：取帧修复

> 适用：**GPU 显示后端**（`display.gpu=1`）。修复在 `native/service_input.hpp`，不影响 GPU 算法、波形与 HWC。
> 一句话：全刷波在 SurfaceFlinger 没出新帧时取到了轮转出来的旧缓冲，于是把上一页当成新画面全刷；
> 现在**只有确认 SF 出了新帧才消费 / 轮转缓冲，否则复用上一次已上屏的帧**。

## 一、现象

- 翻页之后按指纹键、点系统「刷新」或让「自动刷新」跑一次全刷（Clear / GC16），画面**退回上一页 / 上一帧**；
- 紧接着的下一波又把当前页刷回来，观感像「闪一下」或「停在上页」；
- 再全刷一次就正常，之后不一定复现；
- 关掉 `display.gpu` 并完整重启即消失 → 病灶在 GPU 前端的取帧环节。

## 二、根因：三缓冲轮转假定「每波都有新帧」

GPU 输入前端把 SurfaceFlinger 的三块 `AHardwareBuffer` 当成 `raw / pending / prev` 三个角色轮转：

| 环节 | 位置 | 做的事 |
| --- | --- | --- |
| 读当前输入 | `hookTranspose` | 每波开头读 `*VAR_RAW` 得到「本波要显示的帧」 |
| 比对 | `runFront` | GPU 上做转置 + 灰度 + 差异统计（逐像素比较当前帧与上一帧） |
| 收尾轮转 | `hookStore` | 把「上一帧」缓冲轮转成下一个 `raw` 目标，已消费帧成为 `prev` |

这套轮转的前提是**每一波 SurfaceFlinger 都会产出新帧**。但指纹键 / 系统全刷（Clear）由系统发起，
**没有新的合成帧**：`StockBridge::attempt()`（由 SF dump layer 时经 import bridge 调用）不会被触发，
轮转出来的 `raw` 仍是旧内容 —— 前端也察觉不到，因为 `diff` 很大，看起来就是一次正常的大幅变更。

一次实测（`FRONT wave=… input=<当前取到的缓冲> prev=<上一帧缓冲> diff=<差异像素>`）：

| wave | 类型 | input | prev | diff | 说明 |
| --- | --- | --- | --- | --- | --- |
| 277 | 内容 | 0 | 1 | 4760 | 显示旧页 |
| 278 | 内容 | 2 | 0 | 215662 | 翻页 → 显示当前页 |
| **279** | **Clear 全刷** | **0** | 2 | **215662** | 取到 buffer0 = 第 277 波的旧页 |
| 280 | 内容 | 2 | 0 | 214378 | 又切回当前页 |

## 三、修复（`native/service_input.hpp`）

只改取帧，不动 GPU 算法与波形，四处改动：

1. **新增状态与安全开关**
   - `lastConsumed`：上次已上屏的输入槽位；
   - `sfPublishSeq` / `consumedSeq`：SF 实际出帧计数；
   - `frontReuseEnabled()`：读 `debug.eink.front.reuse`，只识别字面 `0` 为关闭，缺省即开启。
2. **计数 SF 出帧**（`importRelease(..., commit=true)`）：SF 真正发布一帧时 `++sfPublishSeq`。
   用 SF 经 import bridge 的实际发布次数做判据，不依赖任何未公开的原厂标志位。
3. **`hookTranspose` 判新鲜度**：`fresh = sfPublishSeq != consumedSeq`；
   没有新帧且 `lastConsumed` 有效时，`frontRaw = lastConsumed`（复用屏上那帧）并打印 `FRONT_REUSE`。
4. **`hookStore` 只在该消费时轮转**：消费后记录 `lastConsumed / consumedSeq`；
   仅当 `frontRaw != prevRaw` 时才把 `VAR_RAW` 指向 `prevRaw`。
   缺这一条判断，复用分支会把 `VAR_RAW` 指到上一帧缓冲，SF 随后覆写它，问题换个形态回来。

## 四、验证口径

1. `logcat -s EinkGPU`，找这次全刷对应的 Clear 波，`FRONT` 的 `input` 应等于**上一波内容帧**，而不是两波前的旧帧；
2. 修复生效时能看到 `FRONT_REUSE wave=… raw=<旧槽> reused=<屏上那帧>`，开机阶段（无新帧的全刷）就会出现；
3. 遥测面：`sys.inkcontrol.ready=1`、`gpu_errors=0`、`cpu_waves=0`，composer 进程号不变；
4. 行为面：翻页 → 指纹键全刷不再回到上一页，滚动 / 锁屏 / 熄屏送图一切照常。

## 五、回退

| 想做什么 | 怎么做 |
| --- | --- |
| 运行时退回旧行为（不重启） | `su -c 'setprop debug.eink.front.reuse 0'` |
| 完全回原厂库 | 从备份取回原厂 `libeinkgpu.so` 覆盖 `payload/`、同步 `checksums.sha256`，完整重启 |

## 六、边界

- 这条链路是取帧最关键的一段：改的是「信谁」（SF 出帧计数），不是「怎么画」，所以 GPU 算法、LUT 与波形行为完全不变；
- 复位 / 模式切换等原本就不产出 GPU 帧的路径，`fresh` 判据同样成立，不需要额外白名单；
- `display.gpu` 关闭时整段逻辑不执行，与独立翻页动画库模式无关。
