# 字体替换机制（参考）

> 适用：海信 A5 Pro 经典版（HLTE203T / Android 10）。本文只保留可直接参照的机制、路径、约束与命令；实验记录、过程数据和历史事故不在此收录。

## 一、结论

1. 字体文件是普通 TTF/OTF，无加密、可无扩展名；文件头为 `00010000` / `OTTO` / `true` / `ttcf`。
2. 系统真正加载的是 `/data/fonts/<id>.ttf`，当前字体由软链 `/data/fonts/HmctFont.ttf` 指向它；sdcard 上的 `.hmcttheme` 目录只是下载缓存，两份文件不会自动同步。
3. 「改同名文件不生效」有两层原因：改的是缓存副本；点当前已选中的字体时主题 App 判定无需变更，不会重新复制。
4. 只换文件也不会生效，必须「激活」——让 framework 重新读取字体并重建界面。
5. 墨控采用「原子替换槽位 + 自动激活」：一次点击全局生效，不用重启任何进程（含桌面与正在运行的应用）。

## 二、目录与标识

| 路径 / 键 | 作用 |
| --- | --- |
| `/storage/emulated/0/.hmcttheme/com.hmct.theme/` | 主题商店下载缓存，文件名 `HITHEME_<显示名>`，通常无扩展名；目录属主 `root:sdcard_rw`、权限 `drwxrwx--x` |
| `/data/fonts/<resourcetid>.ttf` | 系统实际加载的副本，属主 `u0_a78:u0_a78`（`com.hmct.theme` 的 uid 10078），权限 666 |
| `/data/fonts/HmctFont.ttf` | 指向当前字体的软链，每次开机重建；`<id>.ttf` 只在「应用字体」时写入，开机不重写 |
| `/data/fonts/hxfonts.xml` | 软链到 `/system/etc/fonts_vision.xml`，定义 `sans-serif` 家族 |
| `/data/data/com.hmct.theme/databases/data.db` | 表 `resdetailinfo`（`resourcetype=4`）：`resourcetid` 对应文件名、`metainfo` 显示名（`#` 分隔）、`local_file_uri` 指向缓存、`size` 记为官方原始大小 |
| `settings get system system_settings_current_font_name` | 当前字体显示名 |
| `settings get secure pref_key_theme_package` | 当前主题包 |
| `persist.sys.fontfile` / `fontname` / `fontchange` | framework 热更新字体读的三个属性 |

## 三、原厂应用字体的链路

```
设置 → 显示和亮度 → 字体样式
  ├─「下载更多」→ com.hmct.theme 下载到 .hmcttheme/com.hmct.theme/<显示名>
  └─ 点某字体「应用」
       ├─ 缓存文件复制到 /data/fonts/<resourcetid>.ttf
       ├─ 重建 HmctFont.ttf 软链指向该文件
       ├─ 写 system_settings_current_font_name
       └─ 提示/触发重启（字体在进程启动时加载）
```

## 四、墨控的替换与激活

### 4.1 必须原子替换，不能覆盖写

字体被 system_server、SystemUI、桌面等进程 mmap 映射着读。`cp` 覆盖同一 inode 会让仍在映射的进程读到半截数据（`SIGBUS` / 渲染崩溃）。做法是换 inode：

```sh
readlink -f /data/fonts/HmctFont.ttf                 # 当前槽位
[ -s /data/adb/inkcontrol/font-backup.ttf ] || cp <当前槽位> /data/adb/inkcontrol/font-backup.ttf
cp -f <新字体> /data/fonts/<id>.ttf.inknew
chown <原属主> /data/fonts/<id>.ttf.inknew
chmod 666 /data/fonts/<id>.ttf.inknew
chcon <原 SELinux 标签> /data/fonts/<id>.ttf.inknew
sync
mv -f /data/fonts/<id>.ttf.inknew /data/fonts/<id>.ttf
```

约束：

- 新字体必须是合法 TTF/OTF 且**包含中文字形**，否则中文变方块。
- 必须保留原文件的属主、权限与 SELinux 标签，否则 framework 读不到。
- 原厂备份只在第一次替换前生成，之后的替换与恢复都不覆盖它。
- 每个字体落到**独立路径**（如 `/data/fonts/inkcontrol_<md5前8>.ttf`）。framework 的 `Typeface.updateDefaultTypeface()` 按 `persist.sys.fontfile` 的路径字符串判断是否重载，路径不变会直接跳过。

### 4.2 激活四步

仿照主题商店 `com.android.fontOnline` 的 `setFont()`：

```sh
ln -sfn <新字体> /data/fonts/HmctFont.ttf
chown -h system:system /data/fonts/HmctFont.ttf
setprop persist.sys.fontfile  <新字体>
setprop persist.sys.fontname  <文件名去扩展名>
setprop persist.sys.fontchange 1
# 微扰 font_scale：写一次再写回，触发全局 Activity relaunch，不改变用户实际缩放
fs=$(settings get system font_scale); counter=$(( $(cat /data/adb/inkcontrol/font_scale_counter 2>/dev/null||echo 0) + 1 ))
settings put system font_scale "$(awk -v f=$fs -v c=$counter 'BEGIN{printf "%.9f", int(f*100+0.5)/100 + c*0.00000012}')"
settings put system font_scale "$fs"; echo $counter > /data/adb/inkcontrol/font_scale_counter
am broadcast -a hmct.intent.action.FONT_CONFIG_CHANGED
kill $(pidof com.android.systemui)
```

- framework 在 `ActivityThread.handleRelaunchActivity` 看到 `persist.sys.fontchange=1` 时调 `Typeface.updateDefaultTypeface()`，用 `persist.sys.fontfile` 重建 `Typeface.sHmctFontMap` 与 `sDefaults[4]`；`TextView.setTypefaceFromAttrs` 随后取到新字体。
- `fontname` 特例：系统切「默认字体」用 `sans-serif-medium`，framework 对它有无视 `fontfile` 的硬编码分支；`fontfile` 为 `/system/` 路径时也写这个值，保持与系统一致。
- 关键是「路径变了 + 全局 Activity relaunch」，与控件是否显式指定字体族无关。
- 因此**不需要** `setprop ctl.restart zygote`；全局换字已覆盖桌面图标文字。

### 4.3 生效范围

| 对象 | 激活后 |
| --- | --- |
| 状态栏 / 通知栏 / 锁屏 | 立即（SystemUI 重建） |
| 正在运行的应用与桌面 | 立即（`font_scale` 微扰触发全局 relaunch） |
| 桌面图标下的应用名 | 立即（随全局替换一起变） |
| 之后新启动的应用 | 立即 |

### 4.4 后端命令与界面

App 经 `RootBridge` 白名单调用，不接受任意命令：

```sh
inkctl fontlist <目录>    # 输出「文件名 \t 字节数 \t 绝对路径」，只列合法字体
inkctl applyfont <路径>   # 校验字体头 → 原子替换当前槽位 → 恢复属主/权限/标签 → 自动激活
inkctl restorefont        # 备份写回槽位 → 自动激活
```

字体页：路径输入框 +「保存并刷新列表」、选择目录（系统文件夹选择器）、从文件选择（SAF 兜底）、字体列表（名字独占一行，下一行是大小与「应用」）、恢复原厂字体。目录读不到时用 SAF 直接挑文件；TF 卡路径普通应用读不到，所以列表走 root。

## 五、风险与回滚

| 风险 | 对策 |
| --- | --- |
| 字体缺字形 | 应用前确认含中文；一般中文字体 3 MB 以上 |
| 属主/权限/标签写错 | 后端按原文件 `stat` 恢复 |
| 覆盖写入导致崩溃 | 临时文件 + `mv` 原子替换，老进程继续持有旧 inode |
| 备份被后续替换覆盖 | 备份只生成一次 |
| 主题 App 后续覆盖 | 在「字体样式」里切字体会按它自己的逻辑重新复制；重新应用一次即可 |
| 开机重写 `<id>.ttf` | 当前固件不会；若固件改行为，可在开机后校验大小/哈希并在 `service.sh` 重放 |
| 回滚 | 字体页点「恢复原厂字体」，把 `font-backup.ttf` 原子写回槽位后自动激活 |
